# Staticlint - Multichecker для статического анализа

Multichecker объединяет множество статических анализаторов для проверки кода проекта go-musthave-metrics.

## Установка

```bash
go build -o staticlint cmd/staticlint/main.go
```

## Использование

```bash
# Анализ всего проекта
./staticlint ./...

# Анализ конкретной директории
./staticlint ./cmd/agent/...

# Анализ конкретного пакета
./staticlint ./internal/handler/...
```

Или напрямую через go run:

```bash
go run cmd/staticlint/main.go ./...
```

## Включенные анализаторы

### 1. Стандартные анализаторы из golang.org/x/tools/go/analysis/passes

- **asmdecl**: проверка деклараций ассемблера
- **assign**: проверка неиспользуемых присваиваний
- **atomic**: проверка использования sync/atomic
- **bools**: проверка распространенных ошибок с булевыми операциями
- **buildtag**: проверка build тегов
- **cgocall**: проверка вызовов CGO
- **composite**: проверка литералов композитных типов
- **copylock**: проверка копирования мьютексов
- **errorsas**: проверка использования errors.As
- **httpresponse**: проверка использования http.Response
- **ifaceassert**: проверка утверждений интерфейсов
- **loopclosure**: проверка замыканий в циклах
- **lostcancel**: проверка потерянных контекстов
- **nilfunc**: проверка вызовов nil функций
- **printf**: проверка форматирования строк
- **shift**: проверка сдвигов
- **stdmethods**: проверка стандартных методов
- **structtag**: проверка тегов структур
- **tests**: проверка тестов
- **unmarshal**: проверка unmarshal
- **unreachable**: проверка недостижимого кода
- **unsafeptr**: проверка unsafe.Pointer
- **unusedresult**: проверка неиспользуемых результатов

### 2. Все анализаторы класса SA из staticcheck.io

Анализаторы класса SA проверяют корректность использования стандартной библиотеки Go и выявляют потенциальные ошибки.

Примеры:
- **SA1000**: неправильное использование регулярных выражений
- **SA1010**: использование устаревших функций
- **SA2000**: неправильное использование sync.WaitGroup
- **SA4000**: бесконечные циклы
- **SA5000**: присваивание nil map
- **SA6000**: использование sync.Mutex вместо sync.RWMutex

Полный список включает более 100 анализаторов класса SA.

### 3. Анализаторы класса ST из staticcheck.io (стиль кода)

Проверяют соответствие кода стандартам именования и стиля Go.

Примеры:
- **ST1000**: неправильное именование пакетов
- **ST1001**: неправильное именование типов
- **ST1005**: неправильное именование переменных
- **ST1015**: неправильное именование функций

### 4. Дополнительные публичные анализаторы

- **errcheck**: проверка необработанных ошибок
- **ineffassign**: проверка неэффективных присваиваний

### 5. Собственный анализатор

- **exitcheck**: запрещает прямой вызов os.Exit в функции main пакета main

Этот анализатор помогает обеспечить правильное завершение программы через возврат из main или использование других механизмов завершения (например, через fx.Run() или graceful shutdown), что важно для корректной работы тестов и интеграции с системами управления процессами.
